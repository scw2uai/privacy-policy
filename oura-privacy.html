Privacy Policy — Scarlett Health

Effective and last updated: August 12, 2026

Who and what this policy covers

Scarlett Health is a private, noncommercial, single-user personal-wellness integration operated by Scott Wilks for his own use. This policy describes how that integration handles information obtained through the Oura Cloud API. Questions and privacy requests may be sent to scottwilks76@gmail.com.

Information received and retained

The integration requests only the Oura daily OAuth scope and calls only the daily Readiness, daily Sleep, and daily Activity endpoints. Endpoint responses are held temporarily in memory for validation. The integration does not call endpoints for email, personal profile, heart-rate series, workouts, sessions, tags, SpO2, ring configuration, stress, heart health, location, or detailed sleep periods.

After validation, the integration retains only:

  • the Oura document identifier, calendar day, score, and selected documented contributor scores;
  • limited Readiness temperature-deviation fields;
  • limited Activity fields: active calories, target calories, total calories, steps, sedentary time, and non-wear time;
  • connection and synchronization metadata needed to prevent duplicate imports, record freshness, and diagnose bounded errors; and
  • deterministic recovery categories and workout-volume decisions derived from those minimized records.

Full raw API payloads and fields outside this allowlist are discarded after validation. Imported calorie values are stored as Activity facts but are never used to increase or “eat back” a nutrition target.

How the information is used

The information is used only to synchronize and present the operator's personal daily summaries, record freshness, and apply a conservative deterministic rule: same-day Readiness—or Sleep only when Readiness is unavailable—may reduce a suggested workout volume. It cannot increase workout volume, override pain or no-time safety rules, override an explicit user choice, or alter nutrition targets.

Artificial intelligence

Although the broader Second Brain system uses artificial intelligence for unrelated functions, Oura-sourced data and data derived from it are isolated from those functions. They are not sent as prompts or other input to any AI or machine-learning system and are not used for training, fine-tuning, evaluation, embeddings, or model improvement.

OAuth and security

API traffic is protected in transit by HTTPS. OAuth access and refresh tokens and token expiry are stored in one bundle in the logged-in operator's macOS Keychain. Granted scopes are stored in that bundle and also recorded with non-secret connection metadata in SQLite; SQLite stores only a non-secret reference to the Keychain item, not token values. The application code exchanges authorization codes but does not persist them. Authorization state expires after ten minutes, and only a SHA-256 digest of that state is stored.

The minimized database is access-restricted to the operator and resides on the Mac's internal Apple-silicon APFS storage, which uses hardware-backed encryption at rest. The SQLite file is not separately application-encrypted. Any operator-controlled copy or backup containing this database is subject to the same security and deletion commitments.

Disclosure and sharing

The integration does not sell, rent, license, advertise with, or voluntarily disclose Oura-sourced or derived information to advertisers, data brokers, AI services, other users, or unrelated third parties. Information may be disclosed to Oura or its designated auditor when necessary to report or investigate an actual or suspected security or privacy incident or to verify the integration's compliance, and otherwise when required by law.

Retention

Raw endpoint responses exist only during synchronization and are then discarded. OAuth credentials remain until they are disconnected, replaced, or fully deleted. Minimized summaries, synchronization and audit records, and derived daily-status records currently have no automatic expiration and may remain after a temporary disconnect. They are kept only while needed for the ongoing personal integration and are manually deleted when a full-deletion request is completed, when the integration is permanently ended, or when continued processing is no longer authorized because the applicable Oura API agreement ends or is suspended.

Consent, access, opt-out, and deletion

The operator controls consent through Oura's authorization flow and may revoke that consent in Oura at any time. The integration respects the granted scope and Oura privacy settings. Revoking authorization in Oura prevents further authorized API access. Scarlett is not configured to receive a revocation notification, so it may detect an Oura-side revocation only when it next attempts an API request. Corrections to source data should be made in Oura.

Disconnecting inside Scarlett deletes the locally stored OAuth access and refresh tokens, stops future API access, and prevents imported Oura summaries from being used in new workout recommendations. It does not delete previously imported summaries or derived records, and it does not currently revoke the authorization remotely at Oura. Revoking the integration in Oura does not erase copies already transferred to Scarlett.

For access to Oura-sourced and derived information, to opt out, or to request full deletion, email scottwilks76@gmail.com. Upon receipt of an opt-out request, further local processing will cease immediately. Upon a full-deletion request, the operator will stop Oura processing and manually delete all Oura-sourced and derived information in his possession or control—including tokens, imported summaries, Oura-derived daily-status records, integration metadata, and any controlled copies or backups—within 72 hours. Unrelated Second Brain records may remain.

Changes

This policy may be updated when the integration or its data practices change. The effective date above identifies the current version.
